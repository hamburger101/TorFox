# Stage 4 findings (2026-11-15)

What Stage 4 (privacy and security) built, what it found, and what it leaves open. Every claim here comes
from a test in this repository; [`TESTING.md`](TESTING.md) says how to run them. All results were measured
on Windows 11 x64 with CEF 156.0.30 (Chromium 156.0.8078.96), using Release builds. macOS is built by CI
only. None of the Stage 4 behaviour has been run on macOS, and its macOS code has never been compiled.

## Results at a glance
| Suite | Result |
|---|---|
| Unit tests (`torfox_unit_tests`) | 130 run: 129 passed, 1 skipped (`ClearData.NeverFollowsLinks` needs a privilege to create a symbolic link; `ClearData.NeverFollowsJunctions` covers the same rule without one) |
| End-to-end tests (test build) | 174 run, 173 passed. The one failure was `test_settings_service_refusals`, which still used `privacy.httpsFirst` as its example of a planned setting; it now uses `permissions.location` and passes. No expected failures remain: both Stage 1–3 known gaps are closed (§3.5, §3.6) |
| Mutation check (Stage 4 mutations) | 25 of 25 detected, after one test was strengthened (§5) |

## 1. What was built
All of it is in Settings > Privacy & Security, and every setting below is now active (it changes
behaviour, and a test shows it).

### HTTPS-first (on by default)
- An `http://` address typed, clicked or redirected to is tried over `https://` first
  (`TabClient::HttpsFirst`, rules in `src/core/privacy/https_first.cc`).
  - **Upgraded:** public domain names, meaning at least two labels under a top-level domain in the ICANN
    section of the Public Suffix List.
  - **Never upgraded:** IP addresses, `localhost`, single-label (intranet) names, names under non-public TLDs
    (`.local`, `.test`, `.internal`, …), `.onion`, and URLs with an explicit port or user info.
- If the https attempt fails with an error that http might fix, TorFox asks before loading the http
  page. Those errors are connection and certificate failures, not "name not found" or "offline".
  - The question names the site and says plainly that the page and anything typed into it are not encrypted.
  - *Cancel* is the default.
  - An https site that redirects back to http gets the same question, not an endless loop of upgrades.
- A site the user chose to load over http stays on http until TorFox closes. Normal windows share one list
  of such sites, and each private window keeps its own. Nothing is saved.
- **Not upgraded: form posts.** Repeating a POST over https would mean sending the form data again, so a
  form that posts to an `http://` address is sent as it is (§6).

### Tracker blocking (on by default)
- The list is EasyPrivacy's whole-domain rules (47,353 domains), regenerated by
  `scripts/update_trackers.py` from the EasyList repository.
  - The script works from a pinned commit (`third_party/easyprivacy/sources.lock.json`) and checks every
    file's SHA-256.
  - The build refuses a `domains.txt` whose hash differs from the lock. The list is compiled in.
  - Licence: CC BY-SA 3.0, kept apart from TorFox's code ([`third_party/easyprivacy/README.md`](../third_party/easyprivacy/README.md)).
- What is blocked: a request to a listed domain, or a subdomain of one, made by a page of **another** site.
  - "Site" means the registrable domain, using the same Public Suffix List as Chromium.
  - A tracker company's own pages still work when visited directly.
- Blocking happens in `OnBeforeResourceLoad`, for every request type except the page itself.
- **WebSockets are not covered:** CEF does not show them to `OnBeforeResourceLoad` (Stage 3 findings §5;
  see §6).

### Third-party cookies (blocked by default)
- `profile.cookie_controls_mode` is set to 1 in the normal and private contexts, and is always 1 for
  internal pages.
- The setting can be changed while TorFox runs: the pref is set again, verified by reading it back, in every
  open context.

### Pop-ups (blocked without a click, by default)
- Pop-ups never become windows. An allowed pop-up opens as a new tab, with no opener relationship.
- Without a click, a pop-up is refused, and the toolbar says which site tried to open it.
- The setting turns this off; a click-opened pop-up always works.
- There is no per-site list (§6).

### Site permissions
- **Camera and microphone:** *Block* (the default) or *Ask every time*.
- **Clipboard reading:** *Block* (the default) or *Ask every time*.
- **Always denied, not configurable:** location, notifications, screen capture, and every other permission.
  The settings for location and notifications stay marked as planned.
- The question is a native prompt (a TaskDialog on Windows). It names the site, and *Block* is the default.
  The prompt belongs to the tab: closing the tab, or the page withdrawing its request, closes it (not
  tested, §6).
- **No answer is remembered:** each request asks again (§3.4).

### Email and phone links
- `mailto:` and `tel:` links ask first ("… wants to open your email app"), showing the link.
  - They only ask after a click; a page cannot raise the question by itself.
  - Only one question at a time is shown per tab (not tested, §6).
- The URL handed to the operating system is checked first (`external_protocols::LaunchableScheme`):
  - only those two schemes;
  - at most 2,048 bytes;
  - printable ASCII without spaces or `" ' \ < > ^ \` { | }`.
- Every other scheme (`ms-settings:`, `file:`, custom app schemes, …) is refused and never reaches the
  operating system.

### WebRTC
- Web contexts use `webrtc.ip_handling_policy = default_public_interface_only`. Internal pages use
  `disable_non_proxied_udp`.
- A test gathers ICE candidates with no STUN server, where the only possible candidates are the computer's
  own addresses. No local address appears in any candidate or in the session description.

### Clear when TorFox closes (each off by default)
- **History:** TorFox's own history (`places.db`, overwritten in the file), Chromium's per-site records,
  and saved zoom levels.
- **Cookies and site data:** cookies, local and session storage, IndexedDB, service workers, and so on.
- **Cache:** the caches, and the network state that lists recently contacted hosts.
- **When it runs:** the files are deleted after Chromium has shut down, so nothing can rewrite them.
  - Clearing also runs again at the next start, before Chromium opens the profile. That covers a session
    that ended in a crash, or files that were in use.
  - If anything could not be deleted, TorFox says so when it starts (not tested, §6).
- **Links are removed, never followed.** On Windows a directory junction needs no special rights, so
  anything able to write to the profile could plant one. A unit test plants three junctions and checks that
  what they point to survives.
- **Always kept:**
  - preferences;
  - the HSTS list (`Network/TransportSecurity`), which makes later connections safer but could in principle
    help a site recognise a returning browser (§6).

### Proxy settings
There is a new setting, *Use the system's proxy settings* (off by default). Web tabs connect directly
unless it is on (§3.6).

## 2. Changes from the plan
- **HTTPS-first is TorFox's own.** Upgrade, fallback question and per-session exceptions are done in
  `OnBeforeBrowse` and `OnLoadError`. Chromium's built-in HTTPS-First Mode was not used.
- **Permissions are not stored per site.** The plan had per-site decisions managed in Settings. Instead,
  TorFox asks every time and keeps nothing.
  - A list of sites and answers would be a record of browsing.
  - "Ask every time" cannot be quietly widened by a site.
- **Pop-ups have no per-site allow list**, for the same reason; the global switch remains.
- **Clear-on-exit has no downloads category.** TorFox's downloads list is never on disk, and Chromium's
  record of downloads is always erased (Stage 3), so there was nothing for it to do.
- **Location and notifications are always denied.** CEF has no location provider, and TorFox shows no
  notifications, so offering "Ask" would offer something that cannot work.

## 3. What testing found
1. **Chromium's own pop-up blocker hid pop-ups from TorFox.** Chromium refuses a pop-up opened without a
   click before CEF calls `OnBeforePopup`. With that blocker in place, the *Block pop-ups* setting could not be
   turned off, and the user could not be told about blocked pop-ups.
   - TorFox now sets `profile.default_content_setting_values.popups` to allow in web contexts and makes the
     decision itself.
   - The tests cover both directions: blocked with the notice, and allowed with the setting off.
2. **`mailto:` links never reach `OnProtocolExecution`** in CEF 156. A click on one arrives in
   `OnBeforeBrowse` as a navigation, where TorFox's navigation guard refused it as an unknown scheme. Email and
   phone links are now handled there. `OnProtocolExecution` refuses everything, as a backstop.
3. **Mail links opened without a click would have asked anyway.** A page can navigate to `mailto:` from a
   timer. The click check came out of a test of exactly that, and the question now needs a click.
4. **Chromium remembers permission answers per site.** After one answer through `OnShowPermissionPrompt`
   (clipboard), Chromium stored *block* or *allow* for that origin in the profile.
   - Later requests were then answered without asking, and the profile listed every site that had asked.
   - TorFox now resets the content setting to its default right after each answer
     (`CefRequestContext::SetContentSetting`, logged as `permission_forgotten`).
   - The test grants once, then checks that the next request asks again.
   - Camera and microphone go through `OnRequestMediaAccessPermission`, which stores nothing.
5. **Chromium's Preferences file lists the sites visited.**
   - `profile.content_settings.exceptions.site_engagement` and `media_engagement` gain an entry for every
     site visited.
   - `partition.per_host_zoom_levels` holds every zoomed site.
   - None of this was shown in TorFox's history, so clearing history did not touch it (the Stage 2 known gap).
   - **The fix** has three parts:
     - TorFox erases the engagement scores before Chromium starts and after it shuts down, every time
       (`chromium_profile::ScrubSiteRecords`).
     - Zoom levels are erased too when history is cleared on exit.
     - Clearing history from the History page also empties all three prefs at once.
   - The Stage 2 expected failure (`test_clearing_history_forgets_zoomed_sites`) now passes. The clear-on-exit
     control test checks that a visited host is not in Preferences after an ordinary exit.
6. **Proxy auto-discovery (WPAD) is closed.**
   - Stage 1 found that the normal profile's network context starts before TorFox can set its prefs. With
     Windows' *Automatically detect settings* on, it looked for a proxy once at every start (DHCP, then a
     lookup of `wpad`), telling the local network that a browser had started.
   - TorFox now writes the normal profile's proxy mode into its Preferences file before CEF starts
     (`chromium_profile::WriteProxyMode`), so the network context starts with it.
   - Web contexts connect directly unless *Use the system's proxy settings* is on. The quiet-startup test
     now requires that no context uses auto-detect at all. It passes on this machine, where auto-detect is on.
   - A second test turns the setting on and sees the lookup, which shows the first test can detect one.
   - **Trade-off:** on a network that requires a proxy, web pages won't load until the setting is turned on.
     The setting's description says so.
7. **The third-party cookie setting takes effect at runtime.** Changing `cookie_controls_mode` on a live
   context changes behaviour: the "allowed" test turns blocking off in a running TorFox and sees the cookie
   sent. No restart is needed.

## 4. How it is tested
| Test (`tests/e2e/test_privacy.py`) | What it shows |
|---|---|
| `TrackerTest` | A page's script and pixel from listed domains never reach their servers, while an ordinary image from another site loads. The tracker's own site works when visited directly. The setting turns blocking off |
| `HttpsFirstTest` | http is tried over https first, and no http request is ever made when https works. A site without https asks: accepting loads it and remembers it; declining loads nothing. An https→http redirect asks once, with no loop. Local names are not upgraded. The setting turns it off |
| `CookieTest` | A cookie set in a third-party frame is not sent back. First-party cookies work. The setting allows third-party cookies, in a running TorFox |
| `PopupTest` | A pop-up without a click is blocked with a notice, and its page is never requested. A click opens a tab. The setting turns blocking off |
| `PermissionTest` | Camera and microphone are denied by default without asking. With *Ask*, the camera works after accepting, is asked about again next time, and declining denies it. Screen capture, location and notifications are always denied without asking. Clipboard reading is denied, or asked about every time |
| `ExternalProtocolTest` | A clicked mail link asks, showing the link. Without a click it never asks. Declining opens nothing. `ms-settings:` is refused without asking |
| `WebRtcTest` | No local address in ICE candidates or the session description |
| `ClearOnExitTest` | Across real restarts of one profile: a control showing cookie, cache and history survive with clearing off; after a normal exit they are gone from disk, before the next start, including the history database's bytes; after a crash, the next start clears them before any page loads |

Unit tests (`tests/unit/privacy_test.cc`, `chromium_profile_test.cc`, `settings_test.cc`) cover:
- the tracker matcher and the PSL site check;
- the upgrade rules and the fallback error list;
- the external-URL check;
- the clear-on-exit paths, with links and junctions;
- the Preferences edits;
- a read-only settings load that never changes the file.

The quiet-startup test now requires that no context auto-detects a proxy (`test_quiet_startup.py`).

## 5. Mutation check
Stage 4 adds 25 mutations to `tests/e2e/run_mutations.py`, one per protection above. Each removes the
protection from the source, rebuilds, and requires every listed test to fail.

They cover:
- HTTPS-first: skipped, falling back without asking, redirect loops, forgotten exceptions, local names
  upgraded;
- trackers: not blocked, or first parties blocked;
- third-party cookies allowed, and pop-ups allowed without a click;
- permissions: asking by default, granting without asking, clipboard asked by default, answers remembered;
- email and phone links: opened without asking or without a click, quotes allowed, other schemes allowed;
- clear-on-exit: skipped at exit or at start, for files or for history; links followed;
- profile records: per-site scores kept, zoom levels kept after clearing history, and the proxy mode not
  written before start-up.

**Result: all 25 detected.** One needed a stronger test first. `launchable-scheme-allows-quotes`, which lets a
`"` into a mail link handed to the OS, survived the first run. The unit test's only quote case also held a
space, so the space check refused the URL on its own. The test now tries each refused character alone,
and the mutation is detected.

## 6. Not verified, and known gaps
- **Opening the mail or phone app.** Test builds log the decision instead of calling
  `ShellExecuteW` / `NSWorkspace`, so that tests never start a real mail program. The URL check in front of
  it is unit tested; the call itself is not.
- **Form posts to http are not upgraded** (§1). A form on an https page posting to an http address is
  sent unencrypted.
- **Tracker WebSockets are not blocked.** A tracker reached only by WebSocket is not blocked. Third-party
  cookie blocking still applies.
- **The HSTS list is kept** by clear-on-exit (§1).
- **Removing single history entries** does not remove the site's zoom level; only *Clear history* and
  clear-on-exit do.
- **Zoom levels in a running session.** Clearing history empties the saved zoom levels at once, and the test
  checks the file after TorFox exits. Whether tabs that are already open keep their zoom until they
  navigate was not tested.
- **Untested paths:**
  - closing a permission prompt when its tab closes or the page withdraws the request;
  - showing one mail-link question per tab at a time;
  - the start-up notice when clear-on-exit could not delete something, or the proxy mode could not be
    written.
- **WebRTC has two layers here**, and the test shows the outcome, not which layer gave it:
  - TorFox's `ip_handling_policy` pref;
  - Chromium's own mDNS hiding of local addresses.
- **macOS:** none of this has been compiled or run on macOS.
